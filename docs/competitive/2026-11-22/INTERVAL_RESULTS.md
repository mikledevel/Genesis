# Результат проверки диапазонов: кандидат не принят

Дата: 23 ноября 2026. Зафиксированный протокол: INTERVAL_PROTOCOL.md. Исходные результаты находятся в interval-validation; синтетические данные не заменяют продажи клиентов и не являются сравнением с конкурентами.

Dev: seed 10–13; отложенная проверка: seed 100–109. Пять типов рядов, 240 наблюдаемых периодов, 14 полностью скрытых будущих периодов. Два метода, 140 успешных запусков суммарно. После просмотра отложенных результатов параметры не подбирались.

| Тип ряда | Покрытие empirical → split | Ширина empirical → split | Interval score empirical → split |
|---|---:|---:|---:|
| Сезонность | 0.786 → 0.871 | 8.71 → 9.52 | 11.98 → 10.70 |
| Тренд | 0.743 → 0.936 | 9.31 → 13.81 | 13.70 → 14.64 |
| Шум | 0.829 → 0.871 | 39.06 → 40.32 | 50.06 → 46.74 |
| Редкие продажи | 0.721 → 0.864 | 14.48 → 19.53 | 34.61 → 34.73 |
| Ненаблюдаемый будущий сдвиг | 0 → 0 | см. исходный CSV | 564.31 → 564.59 |

Для interval score меньше — лучше. Split расширяет диапазоны и улучшает некоторые случаи, но не проходит критерий по всем слоям: для тренда и редких продаж итоговая оценка ухудшается. Неизвестный будущий сдвиг оба метода не предсказывают.

Решение: empirical остаётся стандартным методом. Split доступен только как экспериментальный параметр; обещания калибровки или гарантированного покрытия нет. Следующий отдельный эксперимент требует заранее определённого протокола и согласованных реальных рядов. Большое число нулей явно понижает оценку надёжности, результат не называется планом закупок.
