## Техническая спецификация первого изменения

Цель — пользователь скачивает результат, который уже получил, с теми же числами. Контракт ниже — проект для реализации, существующим API он не объявляется.

- Маршрут: `GET /api/jobs/{job_id}/report?lang=ru&format=html`, отдельный `format=csv` для таблицы прогноза.
- Требуются вход и точное совпадение владельца. Несуществующий/чужой job — 404. Неподдерживаемые параметры — 422. Не завершённая forecast-job или job другого типа — 409.
- Источник — сохранённый forecast snapshot, не исходный пользовательский путь и не произвольный URL. Никакого вызова LLM или повторного обучения.
- Snapshot версии 1: дата построения, модель и версия, частота, target, horizon, прогноз с интервалами, history для графика, метрики, методы сравнения, предупреждения и явно обозначенное покрытие. Должен сохраняться вместе с результатом задачи.
- Ответ: корректный Content-Type, attachment с безопасным именем, `Cache-Control: no-store`; HTML без скриптов и внешних ресурсов. Для CSV предусмотреть нейтрализацию formula injection в пользовательских строковых полях.
- Legacy-job без достаточного snapshot получает понятную ошибку, а не заново рассчитанный результат под старой датой. Backfill — отдельное явное действие с оценкой стоимости.
- Приёмка: владелец скачивает RU/EN, цифры равны job result, другой пользователь получает 404, повтор не меняет usage, файл работает offline, предупреждение недокалибровки видно, restart не теряет snapshot.

Модель БД/миграцию не добавлять до проверки существующего result/artifact storage: если snapshot помещается в текущий версионированный result JSON, использовать его. Новая таблица ради экспорта не нужна.
