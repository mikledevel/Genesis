# Надёжность LLM-сценариев — 12 ноября 2026

Рабочий план и критерии приёмки:

1. Сквозные evals: воспроизводимый offline-прогон через реальные инструменты, отдельный live-прогон маршрутизации; JSON-отчёт с успешностью, latency и стоимостью.
2. Контракты инструментов: типизированные аргументы, запрет неизвестных полей и инструментов до исполнения, native function calling для поддерживающих моделей.
3. База знаний: проверяемые ссылки на фрагменты, отказ от неподтверждённых источников, сравнение лексического и гибридного поиска на RU/EN наборе.
4. Прогноз: проверка обязательных признаков, типов и конечности чисел; версия модели, метрики и ограничения результата.
5. Трассировка: один trace для запроса, попыток провайдеров, поиска и инструментов; токены, стоимость, ошибки; просмотр только собственных traces.
6. Длительные задачи и файлы: использовать существующие постоянные хранилище и очередь; добавить недостающие операции, статусы, отмену и проверку восстановления.

В репозитории пока нет первого git-коммита, все исходники являются пользовательскими untracked-файлами. Общий baseline-коммит в рамках этой работы не создаётся.

## Что реализовано

| Направление | Реализация |
| --- | --- |
| Evals | `eval/product/agent_eval.py`: offline replay ответов провайдера с настоящей загрузкой, обучением, registry, marketplace, прогнозом и KB; отдельный live routing без исполнения действий. JSON-отчёты содержат успешность, latency, токены и оценку стоимости. |
| Инструменты | `app/core/tool_contracts.py`: общие Pydantic-схемы для function definitions и валидации перед dispatch. Поддерживаются прежние aliases, нормализация имён алгоритмов. JSON mode со строгой серверной проверкой — основной режим по результату live-eval. Native tools доступны через настройку; там обычный ответ идёт через `reply`. Native tools и JSON mode не смешиваются. |
| Источники | Стабильные ID фрагментов, `reply.citations`, проверка принадлежности ссылки реально найденным фрагментам. Выдуманная ссылка отклоняется. В чате видны имя документа и раскрываемый текст; найденные, но не процитированные фрагменты явно обозначены. |
| Поиск | Лексический режим сохранён. Опциональный hybrid объединяет его с локальными multilingual embeddings, имеет отдельные пороги и ограниченный cache. При недоступности optional backend чат использует lexical и пишет техническое событие. Benchmark вызывает hybrid напрямую, поэтому не скрывает такой сбой. |
| Прогноз | Проверяются отсутствующие и неизвестные признаки, конечность чисел (включая слишком большие integers), даты, текст и конечность численного результата модели. Результат содержит `model_version`, family, метрики и ограничения. Decision score явно не называется калиброванной вероятностью. Причинные объяснения не выдумываются. |
| Traces | `app/core/tracing.py`, `app/db/traces.py`: HTTP request ID, actual provider/model, попытки и fallback, retrieval, tool, duration и токены. До 200 traces на аккаунт, максимум 200 spans в trace, очистка через 7 дней. Доступ только владельцу. Сообщения, фрагменты и аргументы в traces не записываются. |
| Задачи и файлы | Существующая постоянная очередь расширена операциями train, forecast, code_generate и model_create. Веб-чат отправляет `background=true`, показывает прогресс/результат и отмену, возобновляет чтение статуса из истории. Повтор request ID не создаёт вторую задачу; агент не продолжает цепочку до окончания задания. При следующем сообщении агент получает актуальный результат задания из БД, а не старое состояние queued. Попытки workers защищены от устаревших записей. Проверяется существующее восстановление файлов из PostgreSQL и dump/restore. |

## Запуск

Перед обновлением сохраните резервную копию. Схема 4 добавляет таблицу traces; существующие данные сохраняются.

```sh
python scripts/backup_db.py
python scripts/migrate.py
python scripts/migrate.py --check
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Лексический режим не требует дополнительных зависимостей. Опциональный hybrid:

```sh
pip install -r requirements-retrieval.txt
python -c 'from app.core.semantic_retrieval import embedding_model; embedding_model()'
# В .env: KB_RETRIEVAL_MODE=hybrid
```

Модель: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, FastEmbed `0.9.1`. Модель скачивается при первом прогреве; тексты обрабатываются локально. Подготовьте cache до приёма запросов. Этот режим требует больше памяти, поэтому он не включён по умолчанию на малом инстансе. Источник API: [FastEmbed](https://github.com/qdrant/fastembed), [native tool calling Groq](https://console.groq.com/docs/tool-use/local-tool-calling).

## API

- `GET /api/traces?limit=30&offset=0`, `GET /api/traces/{id}` — только с session token владельца. `trace_id` приходит в data ответа агента и в результате задания. Traces связывают queued job по `job_id`.
- `estimated_cost_usd` равен `null`, если полная стоимость неизвестна. `known_estimated_cost_usd` — только известная часть по каталогу, `unpriced_calls` и `unmetered_attempts` показывают неполноту. Это оценка, а не счёт провайдера. Тарификация API пользователя остаётся отдельной операцией.
- `POST /api/jobs`, `GET /api/jobs`, `GET /api/jobs/{id}`, `DELETE /api/jobs/{id}`. Поддерживаются `train`, `forecast`, `retrain`, `improve`, `model_build`, `model_create`, `code_generate`. Создание требует прав на данные/модель и платного плана.
- Train payload: `{"path":"datasets/uploads/<owner>/file.csv","target_column":"churn","model_type":"logistic","budget":"fast"}`. Forecast добавляет `date_column`, `horizon`, `horizon_unit`. Для retrain/improve используются `model_id` и `dataset_path`.
- Для прямого POST jobs используйте `Idempotency-Key`. Для чата — `request_id` и `background:true`. API-клиенты могут сохранить прежний синхронный режим, опустив background.
- `AGENT_TOOL_PROTOCOL=json` — основной режим; `native` или `auto` включает function calling, если он указан в каталоге возможностей модели. Серверная проверка аргументов обязательна при любом протоколе.

## Воспроизводимые проверки

```sh
python scripts/check_backend.py tests/ -q --tb=short
python eval/product/agent_eval.py --output docs/evals/workflow.json
python eval/product/retrieval_eval.py --output docs/evals/retrieval.json
# Следующая команда делает реальные LLM-вызовы и расходует квоту провайдера:
python eval/product/agent_eval.py --mode live --interval-seconds 45 --output docs/evals/routing.json
node tests/ui/ui_test.js
node tests/ui/admin_test.js
node tests/ui/antibot_test.js
```

Offline workflow работает в отдельном временном каталоге и не открывает пользовательскую БД. Live routing также использует временную БД, но читает настроенные ключи провайдера; инструменты не исполняет. При наличии Groq проверяется выбранная модель Groq без fallback на другую модель. Пауза между запросами нужна для TPM-лимита; latency измеряется без этой паузы. Провайдерный `tool_use_failed` допускает одну повторную генерацию, затем обычную цепочку ошибок/fallback. `failed_generation` никогда не исполняется.

## Результаты и практические границы

- Offline workflow: **12/12**, включая уточнение неоднозначного target до обучения. Реальные инструменты с воспроизведёнными ответами LLM; это не оценка качества живой модели. Отчёт: `docs/evals/workflow_2026-11-12.json`.
- Live routing `openai/gpt-oss-120b` на Groq: JSON **11/12**, медиана **629 ms**, p95 **995 ms**, известная оценка стоимости **$0.0056424** за набор. Инструменты во время live-eval не исполнялись. В одном случае выбран правильный forecast tool, но не передан явно названный target. Это оставшаяся ошибка, а не успешная проверка. Отчёт: `docs/evals/routing_json_2026-11-12.json`.
- Native routing с одним ограниченным повтором генерации: **8/12**, медиана **943 ms**. Две ошибки аргументов/выбора действия и два сетевых таймаута; полная стоимость неизвестна. Отчёт: `docs/evals/routing_native_2026-11-12.json`. Прогоны небольшие и последовательные, это не статистически строгий A/B-тест. JSON оставлен основным, native — доступным для дальнейших экспериментов.
- Retrieval heldout на Python 3.12 с основным lockfile: lexical **8/14** top-1, hybrid **11/14**; корректный отказ для обоих **3/6**. Медиана прогретого retrieval около **0.21 / 3.68 ms** на этой машине. Первый запуск включает загрузку/индексацию, время прогрева не является временем обычного запроса. Отчёт: `docs/evals/retrieval_2026-11-12.json`, включая версии библиотек, hash набора и SHA-256 ONNX-весов.
- Набор retrieval небольшой и синтетический, с отдельными dev/heldout split. Это начальная проверка, а не доказательство качества на документах клиента. Порог не менялся по результатам heldout. Ошибки отказа сохраняются; поэтому hybrid остаётся opt-in.
- Цитата подтверждает наличие фрагмента, но не логическое следование всего ответа из него. Semantic entailment здесь не проверяется; отсутствие ссылки явно видно, выдуманная ссылка блокируется.
- Отмена останавливает worker, но уже завершённые побочные эффекты не откатываются. После аварии незавершённая задача может быть выполнена повторно; exactly-once обучение не обещается. Результат старой попытки не перезаписывает новую.
- Поддерживаемое постоянное хранилище файлов уже существовало: до 64 MiB на файл и 500 MiB на аккаунт в PostgreSQL. Для SQLite каталоги файлов резервируются отдельно. Переключение DATABASE_URL не переносит старые локальные файлы автоматически.
- Production deployment, реальные платежи и внешние сообщения в рамках этой работы не выполнялись.

## Приёмочная проверка

- Python **3.12.15**, зависимости из `requirements.lock.txt`, изолированная копия и одноразовый PostgreSQL: **1102 passed, 6 skipped**, 8 subtests, **183.49 s**. Пропуски: три контейнерных теста и jsdom внутри очищенной Python-копии (запущены отдельно), два теста внешнего Basecamp-корпуса (не запускались; synthetic RU/EN retrieval eval выполнен отдельно).
- Настоящий Docker, изоляция исполнения и внешних моделей, guarded network bridge: **3 passed**.
- Все три jsdom-набора — workspace, admin, antibot — прошли, включая новые источники, фоновые результаты, отмену и retry статуса.
- Playwright: вход в изолированный аккаунт, открытие сохранённого диалога с источниками и результатом реального фонового обучения; раскрытие источника клавиатурой. На 320/768/1024/1440 px нет горизонтального переполнения; ошибок и предупреждений консоли нет. Скриншоты: `docs/evals/ui/`.
- `pip check` и компиляция Python-модулей прошли. Основной набор также проверялся на локальном Python 3.14; для приёмки используется результат Python 3.12 с lockfile.
- Сводка с hash lockfile и метриками: `docs/evals/verification_2026-11-12.json`.

Реализованы все шесть направлений. Пороговые значения качества живой LLM не объявляются достигнутыми автоматически: зафиксированы оставшиеся ошибки live routing и отказов retrieval. Миграция production и deployment остаются отдельными операциями.
